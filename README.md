# JAC Parts Bot

Telegram-бот каталога запчастей JAC. Сейчас готово: запуск в Docker, база PostgreSQL,
регистрация «Язык → Регион → Номер телефона», после которой бот сразу открывает каталог
«Модель → Категория → Деталь» на трёх языках с листанием страниц.
Внизу экрана — постоянное меню (как в EVOS): 🛍 Каталог · 🛒 Корзина · 📦 Мои заказы · 👤 Профиль · 📞 Менеджер.
В профиле можно сменить номер, регион и язык. Если у детали есть фото — оно показывается в карточке.
Администратор загружает каталог, цены и остатки из Excel прямо в Telegram (`/admin`).
В карточке детали — дилеры региона покупателя с ценой и наличием и кнопка «🛒 В корзину»;
в корзине можно менять количество (не больше остатка) и оформить заказ. Администратор получает уведомление
и меняет статус кнопками, покупатель видит историю в «📦 Мои заказы» и получает уведомления о статусе.

## Что нужно заранее

- Сервер (или компьютер) с **Debian 12** и доступом в интернет.
- Доступ к серверу по SSH под пользователем с правами `sudo`.
- Аккаунт Telegram.

Белый IP и домен **не нужны** — бот сам ходит в Telegram (long polling).

## Шаг 1. Получить токен бота

1. В Telegram откройте **@BotFather**.
2. Отправьте `/newbot`.
3. Введите название бота (например, `JAC Parts`).
4. Введите username — должен заканчиваться на `bot` (например, `jac_parts_uz_bot`).
5. BotFather пришлёт токен вида `1234567890:AAH...`. **Это пароль от бота — никому не показывайте.**

## Шаг 2. Узнать свой Telegram ID (для админа)

1. Откройте в Telegram **@userinfobot** и нажмите Start.
2. Он пришлёт число `Id: 123456789` — это ваш ID.

## Шаг 3. Установить Docker на Debian

Выполните команды по одной на сервере:

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/debian $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

Разрешить своему пользователю работать с Docker без `sudo`:

```bash
sudo usermod -aG docker $USER
```

После этого **выйдите из SSH и зайдите снова**.

Проверка:

```bash
docker --version
docker compose version
docker run --rm hello-world
```

Должно появиться `Hello from Docker!`.

Docker сам включится после перезагрузки сервера (проверить: `sudo systemctl is-enabled docker` → `enabled`).

## Шаг 5. Создать файл .env

```bash
cp .env.example .env
nano .env
```

Заполните:

```ini
BOT_TOKEN=1234567890:AAH...ваш_токен
ADMIN_IDS=123456789
POSTGRES_DB=jac_parts
POSTGRES_USER=jac_bot
POSTGRES_PASSWORD=придумайте_длинный_пароль
POSTGRES_HOST=postgres
POSTGRES_PORT=5432
DATABASE_URL=
LOG_LEVEL=INFO
```

- Несколько админов — через запятую: `ADMIN_IDS=123456789,987654321`.
- `DATABASE_URL` оставьте пустым — бот соберёт его сам.
- Пароль БД может содержать любые символы. Сгенерировать надёжный можно так: `openssl rand -hex 16`.
- ⚠️ Пароль запоминается базой при **первом** запуске. Если потом поменять его в `.env`, бот не сможет подключиться (`password authentication failed`).

Сохранить в nano: `Ctrl+O`, `Enter`, выйти: `Ctrl+X`.

Закрыть файл от чужих глаз:

```bash
chmod 600 .env
```

> ⚠️ Файл `.env` уже в `.gitignore` — он никогда не попадёт в Git. Не отправляйте его никому.

## Шаг 6. Запуск

```bash
docker compose up -d --build
```

Первый раз займёт 1–3 минуты (скачиваются образы). Что происходит:

1. Запускается PostgreSQL.
2. Когда база готова, запускается контейнер бота.
3. Бот применяет миграции (создаёт таблицу `users`) и начинает принимать сообщения.

Проверить, что оба контейнера работают:

```bash
docker compose ps
```

Ожидаемо: у `postgres` статус `Up (healthy)`, у `bot` — `Up`.

## Веб-панель (только локальная сеть компании)

Сайт для сотрудников: заказы, дилеры, клиенты, каталог и переводы, загрузка Excel, сотрудники и роли. Работает в том же
`docker compose`, что и бот (сервисы `web` и `proxy`), и открывается **только внутри локальной сети** — снаружи его не видно.

### Настройка (один раз) — адрес https://partsbot.jacmotors.uz

Панель открывается по HTTPS через сервис `proxy` (nginx) с сертификатом `*.jacmotors.uz`.
Сама панель (сервис `web`) наружу не открыта — к ней ходит только `proxy`.

1. **Сертификат на сервер.** Файлы `certs/fullchain.crt` и `certs/private.key` в git **не попадают** (это секрет) —
   скопируйте их с компьютера на сервер отдельно:
   ```
   scp C:\Users\USer\Downloads\jac-parts-bot\certs\fullchain.crt C:\Users\USer\Downloads\jac-parts-bot\certs\private.key пользователь@192.168.48.103:~/parts_bot/certs/
   ```
   На сервере закройте ключ от чужих глаз: `chmod 600 ~/parts_bot/certs/private.key`.
   `fullchain.crt` = сертификат сайта + промежуточный из ca-bundle (в таком порядке). Если будете собирать сами —
   между файлами должен быть перевод строки, иначе nginx не запустится (`bad end line`).
2. **Имя в локальной сети.** Попросите IT добавить во **внутренний DNS** запись
   `partsbot.jacmotors.uz → 192.168.48.103`. Пока записи нет — на отдельном компьютере можно добавить строку
   `192.168.48.103 partsbot.jacmotors.uz` в файл `C:\Windows\System32\drivers\etc\hosts` (открыть Блокнотом от администратора).
   Открывать по IP (`https://192.168.48.103`) не надо — браузер покажет предупреждение: сертификат выдан на имя.
3. В `.env`:
   ```ini
   WEB_URL=https://partsbot.jacmotors.uz
   WEB_BIND=0.0.0.0
   BOT_USERNAME=имя_вашего_бота
   ```
   (строку `WEB_PORT` можно удалить — больше не используется.)
4. Порты 80 и 443 должны быть свободны: `sudo ss -ltnp | grep -E ':(80|443) '` — пусто = свободны.
5. `docker compose up -d --build` → `docker compose ps`: `web` и `proxy` в статусе `Up`.
6. Откройте **https://partsbot.jacmotors.uz** — слева от адреса замок. `http://…` сам переходит на `https://`.

**Продление сертификата.** Текущий действует **до 28.11.2026**. Новый: положите новые `fullchain.crt` и
`private.key` в `~/parts_bot/certs/` и выполните `docker compose restart proxy`. Проверить срок:
`openssl x509 -in ~/parts_bot/certs/fullchain.crt -noout -enddate`.

### Вход

- **Администратор** (из `ADMIN_IDS`): в боте `/panel` (или `/admin` → 🌐 Веб-панель) → **🔑 Получить пароль**.
  Бот пришлёт логин и пароль. Пароль показывается один раз — сохраните его и удалите сообщение.
- **Сотрудник:** администратор в панели → **🔐 Сотрудники** → выбрать роль → **Создать приглашение** → переслать
  ссылку сотруднику в Telegram. Сотрудник открывает её — бот сразу присылает ему логин и пароль.
- **Забыли пароль:** `/panel` → **🔑 Новый пароль** (старый перестаёт работать, все входы завершаются).
- 5 неверных попыток — вход с этого компьютера блокируется на 5 минут. Вход действует 12 часов.

### Роли

| Роль | Что может |
|---|---|
| Администратор | всё, включая сотрудников (приглашать, менять роль, отключать, новый пароль) и журнал действий |
| Менеджер | всё, кроме сотрудников и журнала: заказы, статистика, дилеры, клиенты, каталог и переводы, загрузка Excel, рассылки, настройки |
| Оператор | заказы: принять, отменить, сменить статус, написать клиенту; смотреть клиентов и каталог |
| Наблюдатель | только смотреть: заказы, статистика, дилеры, клиенты, каталог |

Люди из `ADMIN_IDS` — всегда администраторы (менять их можно только в `.env`). Себе роль изменить или отключить себя нельзя.
После смены роли сотруднику нужно войти заново.

  по какой цене и сколько. Вкладка **«Без перевода»** → откройте деталь → впишите русское и узбекское название →

  синхронизации. Категория, скрытие, фото, описание — в боте сразу; модели — через 1–2 минуты (синхронизация
  запускается сама). Все изменённые детали — вкладка **«Изменённые»**; «Сбросить правку» — снова как в CarSale.
- **📥 Загрузка Excel** — то же, что загрузка файла в боте: выберите файл → **Проверить** → панель покажет, что

## Синхронизация с CarSale (автоматически)

Сервис `sync` сам входит в **app.carsale.uz** под учётной записью бота, читает «Запчасти → Список запчастей»
и обновляет цены и остатки в боте — так же, как ручная загрузка Excel. API у CarSale нет, поэтому сервис
работает как обычный браузер (Chromium): вписывает логин и пароль, ставит фильтры, читает таблицу.

**Почему не «Экспорт в Excel»:** CarSale показывает и выгружает не больше 1000 строк за раз, а записей больше
(ручная выгрузка на 1000 строк была неполной). Листать страницы тоже нельзя — в CarSale ошибка: при 500/1000 строк
на странице вторая страница начинается с 51-й записи, строки повторяются и теряются. Поэтому сервис ставит фильтр
«Статус: У дилера» и читает **каждого дилера отдельно** (у одного дилера меньше 1000 строк).

**Проверки — если хоть одна не прошла, остатки в боте не меняются:**
- по каждому дилеру сумма «Кол-во» в строках = итогу «Кол-во у дилера», который показывает CarSale;
- сумма по всем дилерам = общему итогу CarSale;
- синхронизация не скроет больше 30% деталей за раз (защита от «CarSale отдал не всё»).
При ошибке администраторы получают сообщение в Telegram (один раз, а не каждые 30 минут), при восстановлении — тоже.

### Настройка (один раз)

1. В `.env` на сервере добавьте (образец — в `.env.example`):
   ```ini
   CARSALE_LOGIN=partsbot
   CARSALE_PASSWORD=пароль_от_CarSale
   CARSALE_SYNC_MINUTES=30
   CARSALE_SKIP_DEALERS=test diler
   ```
2. `docker compose up -d --build` — первый раз сборка сервиса `sync` займёт несколько минут
   (в образе есть браузер, он большой ~1,5 ГБ).
3. Проверка: `docker compose logs -f sync` — должно быть «CarSale: вход выполнен», затем строки по каждому
   дилеру и «CarSale sync … ok». Одна синхронизация занимает 3–5 минут.
4. В веб-панели: **🔄 CarSale** — история синхронизаций и кнопка **«Синхронизировать сейчас»**.

**Выключить:** `CARSALE_SYNC_MINUTES=0` (только по кнопке) или `docker compose stop sync`.
**Сменили пароль в CarSale** — поменяйте `CARSALE_PASSWORD` в `.env` и выполните `docker compose up -d sync`.

Если CarSale изменит страницу (переименует кнопки или фильтры), синхронизация остановится с понятной ошибкой
в панели, а остатки в боте останутся прежними. Пока это не исправлено, загружайте Excel вручную.

### Продажи бота → CarSale (расход с дилера)

Когда заказ в боте получает статус **🟢 Выдан**, сервис `sync` открывает в CarSale
«Перемещение → Заказы запчастей → **Оформить заказ**» и заполняет: дилер, клиент (ищет по имени и телефону,
не нашёл — «Добавить клиента», Физ. лицо), запчасти с количеством, в «Примечании» —
`JAC Parts Bot · заказ №10005 · Имя +998…`. Такой заказ в CarSale сразу «Заказ реализован» — это расход с дилера.

Режим — `CARSALE_ORDERS` в `.env`:

| Значение | Что делает |
|---|---|
| `off` | ничего не записывает |
| `dry` | **пробный режим**: заполняет форму, **не сохраняет** (нажимает «Отмена») и присылает администраторам скриншот — проверьте, всё ли верно |
| `on` | заполняет и нажимает «Сохранить» |

Начните с `dry`: выдайте 1–2 заказа в боте, проверьте скриншоты в Telegram, потом поставьте `on`
и выполните `docker compose up -d bot sync`.

**Защита от двойного списания:**
- на каждый заказ — одна запись (в панели **🔄 CarSale → Продажи бота в CarSale**);
- ошибка ДО «Сохранить» (нет дилера, нет запчасти, не хватает остатка) — статус «⚠️ ошибка», в CarSale ничего не записано, кнопка «↻ Повторить»;
- ошибка ПОСЛЕ «Сохранить» или перезапуск сервиса во время записи — «❓ проверить»: бот **сам не повторяет**.
  Найдите в CarSale заказ по Примечанию: есть — «✓ Записан вручную», нет — «↻ Повторить»;
- пока заказ ждёт записи в CarSale, его детали не возвращаются в остаток при синхронизации.

Ограничение: если нужное количество есть у дилера только в нескольких партиях (разные строки CarSale с одним кодом),
бот не оформляет заказ, а просит сделать его вручную.

## Загрузка каталога из Excel (для администратора)

Доступно только Telegram ID из `ADMIN_IDS` в `.env`. Остальным команда `/admin` ничего не покажет.

1. Отправьте боту `/admin` → **📄 Шаблон Excel** — бот пришлёт файл-шаблон с примерами.
2. Заполните лист **parts**: одна строка = одна деталь у одного дилера.
   Жёлтые колонки обязательные, голубые можно оставить пустыми. Подсказки — на листе **инструкция**.

   | Колонка | Обязательная | Пример |
   |---|---|---|
   | `region` | да | Ташкент (как в боте, на любом из 3 языков) |
   | `dealer` | да | JAC Ташкент №1 |
   | `model_ru` / `model_en` / `model_uz` | ru — да | JAC JS4 |
   | `node_ru` / `node_en` / `node_uz` | ru — да | Двигатель / Engine / Dvigatel (категория) |
   | `part_name_ru` / `_en` / `_uz` | ru — да | Масляный фильтр / Oil filter / Moy filtri |
   | `part_number` | да | 101001 |
   | `price` | да | 85000 (сум, больше 0) |
   | `stock` | да | 12 (0 = нет в наличии) |
   | `delivery_days` | нет | 3 |
   | `description_ru` / `_en` / `_uz` | нет | |
   | `photo` | нет | https://.../photo.jpg |

3. `/admin` → **📥 Загрузить Excel** → отправьте файл.
4. Бот проверит каждую строку. Если есть ошибки — покажет номера строк (как в Excel) и **ничего не изменит**.
5. Если ошибок нет — покажет, сколько деталей добавится, обновится и скроется. Нажмите **✅ Применить** или **❌ Отмена**.

Важно:

- **Файл — это полный прайс.** Детали, которых нет в файле, скрываются из бота (не удаляются). Цены дилеров, которых нет в файле, удаляются.
- Если в переводе (`_en`, `_uz`) пусто — бот покажет русское название, а старый перевод в базе сохранится.
- Импорт выполняется одной транзакцией: при любой ошибке записи база остаётся прежней.
- Ограничения: файл до 10 МБ, до 50 000 строк.
- Демо-каталог после первого настоящего импорта скрывается автоматически.

### Складская выгрузка («Список запчастей»)

Вместо шаблона можно отправить **обычную выгрузку со склада** (лист «Запчасти», колонки «Код запчасти», «На Дилера» и т.д.) — бот сам узнает формат
(в предпросмотре будет «📦 Формат: складская выгрузка») и переведёт её в каталог:

| В выгрузке | В боте |
|---|---|
| Код запчасти | артикул |
| Название запчасти | название: перевод на русский и узбекский из словаря `app/data/part_names.json` |
| Тип запчасти A / B / C / D / TOOLS | категория: ТО и расходники / Кузов / Тормоза и ходовая / Электрика и электроника / Инструменты |
| Автомобильная марка (T8-P30BF, M3…) | модель; «—» → раздел **«Прочее»** (если детали нет в справочнике запчастей) |
| На Дилера | дилер |
| Цена реализации (если 0 — Цена продажи) | цена |
| Кол-во | остаток; несколько строк одной детали у одного дилера складываются |
| Статус | берутся только строки «У дилера»; бронь, реализованные, «в пути» и склад пропускаются |

### Список запчастей завода (модель → артикул → название)

Файлы с колонками `MODEL`, `part code` / `PARTS CODE`, `Spare part name` / `EN NAME` / `DESCRIPTION(EN)`
(колонка `SN` не важна). Остатков и цен в них нет — это справочник: какая деталь к какой модели подходит.

- Загружается так же: панель → «Загрузить Excel» или `/admin` → «📥 Загрузить Excel». Формат определится сам.
- Ничего не скрывает и не удаляет: списки **дополняют** друг друга, модели одного артикула из разных файлов объединяются.
- Зачем: в CarSale у многих деталей модель «—», и в боте они попадали в «Прочее» (раньше «Все модели»). Теперь модель берётся
  из справочника, и деталь показывается в своей модели (одна деталь может быть в нескольких моделях).
- После загрузки бот сам просит сервис sync синхронизироваться сразу — через минуту модели в боте обновятся.
- Коды моделей → названия в боте: `MODEL_NAMES` в `app/services/import_mapping.py`.

### Справочник дилеров

Файл со списком дилеров (колонки **Название, Код, Адрес, Район, Номер телефона, Статус**) загружается так же:
`/admin` → **📥 Загрузить Excel**. Бот узнает формат («📇 Формат: справочник дилеров») и возьмёт из него
**регион, адрес и телефон** каждого дилера. Дилеры со статусом «Неактивный» покупателям не показываются.

Названия в справочнике и в складской выгрузке могут отличаться («OOO «ASIAMOTOR»» и «"Asia Motor" MChJ») —
бот сравнивает их без ООО/MChJ/LLC/ИП, кавычек, пробелов и дефисов. Справочник достаточно загрузить один раз
и потом — когда в нём что-то меняется. Порядок загрузки не важен.

Настройки складской выгрузки лежат в **`app/services/import_mapping.py`** — там можно без знания Python поменять:

- `DEALER_REGIONS` — регион для дилеров, которых **нет в справочнике** (остальные попадают в Ташкент — бот предупредит списком);
- `MODEL_NAMES` — название модели для кода из выгрузки (`"T8-P30BF": "JAC T8"`, `"RF8-V9AA3": "JAC RF8"`). Если в выгрузке появится новый код — бот предупредит;
- `CATEGORIES` — названия категорий на 3 языках;
- `PRICE_COLUMN` — какую цену показывать.

**Переводы названий деталей** лежат в `app/data/part_names.json` (246 названий из выгрузки):

```json
"engine oil filter assy.": { "ru": "Масляный фильтр", "uz": "Moy filtri" },
```

Регистр букв и лишние пробелы в названии не важны. Если в новой выгрузке появится название без перевода —
бот покажет его по-английски и перечислит такие названия в предпросмотре.

**Проще всего переводить в веб-панели:** «📦 Каталог» → «Без перевода». Такой перевод главнее JSON-словаря,
применяется сразу и сохраняется при новых загрузках. Править JSON нужно только если хотите, чтобы перевод был
в коде (тогда: `git push` → на сервере `git pull && docker compose up -d --build` → загрузите файл заново).

  (дешевле — выше), потом «🔴 Нет в наличии». Если в регионе детали нет — бот подскажет, есть ли она в других регионах.

- **🛒 Корзина** в нижнем меню: ➖ / ➕ / ✖️ для каждой позиции, 🗑 Очистить, итоговая сумма.
  Если после новой загрузки Excel деталь закончилась — позиция помечается и не входит в сумму.

## Дилеры в боте: приём заказов и переписка с клиентом

**Подключить сотрудника дилера:** `/admin` → 🏢 Дилеры → нужный дилер → **🔗 Пригласить сотрудника**.
Бот пришлёт ссылку `https://t.me/<бот>?start=dealer_…` — перешлите её менеджеру дилера.
Ссылка одноразовая и действует 7 дней. Менеджер открывает её, проходит обычную регистрацию (язык, регион, телефон) —
и становится сотрудником дилера. Администраторам придёт уведомление. У дилера может быть несколько сотрудников;
отключить — **👥 Сотрудники** → ✖️.

**Сотрудник дилера:**
- получает каждый новый заказ своего дилера (с телефоном клиента) и кнопки статуса — как у администратора;
- внизу у него есть кнопка **📋 Заказы дилера** — все заказы только его дилера, по вкладкам;
- видит и меняет только заказы своего дилера.

Подтвердить / сменить статус может **любой**: сотрудник дилера или администратор. Остальные участники получают
короткое уведомление, кто что сделал («🔔 Заказ №10004: 🔵 Подтверждён · "Asia Motor" MChJ: Dilshod»). Клиент — всегда.
Заказ принимается целиком: менять количество и цену нельзя.

**Переписка через бота** (номера и аккаунты не раскрываются, всё сохраняется в таблице `order_messages`):
- у клиента в заказе — **💬 Написать дилеру**; у сотрудника и администратора — **💬 Написать клиенту**;
- можно отправить текст или фото с подписью; получатель видит «💬 Сообщение по заказу №…» и кнопку **↩️ Ответить**;
- если у дилера ещё нет сотрудников в боте — сообщения клиента получают администраторы;
- «❌ Отмена» — выйти, ничего не отправляя.

Позвонить тоже можно: клиент видит телефон дилера, дилер — телефон клиента.

## Заказы

1. Покупатель: **🛒 Корзина → ✅ Оформить заказ** → экран «Проверьте заказ» → **✅ Подтвердить заказ**.
   Если детали у нескольких дилеров — создаётся отдельный заказ на каждого дилера.
2. Бот ещё раз проверяет наличие. Если пока покупатель думал, деталь купили — заказ не создаётся,
   бот пишет, сколько осталось. Если всё в порядке — количество **резервируется** (вычитается из остатка дилера).
3. Все администраторы из `ADMIN_IDS` и сотрудники дилера получают «🔔 НОВЫЙ ЗАКАЗ №10001» с данными клиента и кнопками статуса:

   | Статус | Кнопки у администратора |
   |---|---|
   | 🟡 Новый | ✅ Подтвердить · ❌ Отменить |
   | 🔵 Подтверждён | 🟠 Готов к выдаче · ❌ Отменить |
   | 🟠 Готов к выдаче | 🟢 Выдан · ❌ Отменить |
   | 🟢 Выдан / 🔴 Отменён | — (конечные статусы) |

   При каждой смене статуса покупателю приходит уведомление. При отмене зарезервированные детали возвращаются в остаток.
4. **📦 Мои заказы** — последние 10 заказов; можно открыть любой. Пока заказ «Новый», покупатель может его отменить сам.

> Администратор должен хотя бы раз нажать **Start** в боте — иначе Telegram не разрешит боту ему писать.
> Номера заказов начинаются с 10001. Время показывается по Ташкенту (`TIMEZONE` в `.env`, по умолчанию `Asia/Tashkent`).

## Резервная копия (backup) — делается сама

В `docker-compose.yml` есть контейнер **backup**. Он делает копию базы:

- сразу при запуске (`docker compose up -d`) — чтобы было видно, что всё работает;
- каждый день в **03:00 по Ташкенту**;
- копии лежат в папке **`~/parts_bot/backups/`** (`jac_parts_2026-09-28_0300.sql.gz`), старше **14 дней** удаляются.

Проверить:

```bash
docker compose logs backup      # «backup OK: /backups/jac_parts_....sql.gz (24K)»
ls -lh ~/parts_bot/backups
```

**Копия на сервере не спасёт, если сломается сам сервер.** Поэтому время от времени забирайте копию к себе:
`/admin` → **💾 Последний backup** — бот пришлёт свежий файл прямо в Telegram (сохраните его, например, в «Избранное»).

Сделать копию вручную прямо сейчас:

```bash
docker compose exec -T postgres pg_dump -U jac_bot -d jac_parts --no-owner | gzip > ~/parts_bot/backups/jac_parts_$(date +%F_%H%M)_manual.sql.gz
```

Время и срок хранения меняются в `docker-compose.yml` → `backup` → `BACKUP_TIME`, `BACKUP_KEEP_DAYS`.

## Восстановление из backup

> ⚠️ Восстановление **заменяет всю базу** содержимым копии. Всё, что было после копии, пропадёт.

```bash
cd ~/parts_bot
ls backups                                    # выберите файл
docker compose stop bot backup
docker compose exec -T postgres psql -U jac_bot -d postgres -c "DROP DATABASE jac_parts WITH (FORCE);"
docker compose exec -T postgres psql -U jac_bot -d postgres -c "CREATE DATABASE jac_parts;"
gunzip -c backups/ИМЯ_ФАЙЛА.sql.gz | docker compose exec -T postgres psql -U jac_bot -d jac_parts
docker compose start bot backup
docker compose logs --tail 20 bot
```

Если в `.env` другой `POSTGRES_USER` или `POSTGRES_DB` — подставьте их вместо `jac_bot` и `jac_parts`.

Копию из Telegram сначала загрузите на сервер (с компьютера): `scp jac_parts_....sql.gz user1@IP_СЕРВЕРА:~/parts_bot/backups/`

2. **Админы:** каждый Telegram ID из `ADMIN_IDS` хотя бы раз нажал **Start** в боте (иначе бот не сможет им писать).
3. **Справочник дилеров:** `/admin` → 📥 Загрузить Excel → файл дилеров → ✅ Применить.
4. **Каталог:** `/admin` → 📥 Загрузить Excel → складская выгрузка → проверьте предупреждения → ✅ Применить.
   Демо-детали после этого скроются сами.
5. **Сотрудники дилеров:** `/admin` → 🏢 Дилеры → дилер → 🔗 Пригласить сотрудника → переслать ссылку.
6. **Пробный заказ:** со своего телефона как покупатель → проверьте, что пришло уведомление админу и дилеру,
   смените статус до «🟢 Выдан», напишите через «💬».
7. **Backup:** `/admin` → 💾 Последний backup — файл пришёл.
8. **Регулярно:** загружайте свежую выгрузку (например, каждое утро) — цены и остатки обновятся.
   Детали из незакрытых заказов бот сам вычтет из новых остатков (в предпросмотре — строка «🔒 Вычтено…»).

**Если в боте что-то сломается**, администраторы получат сообщение «⚠️ Ошибка в боте» с местом ошибки
(одинаковые ошибки — не чаще раза в 10 минут). Пришлите его и вывод `docker compose logs --tail 100 bot` разработчику.

Логи не заполнят диск: у каждого контейнера хранится не больше 5 файлов по 10 МБ.

## Если что-то пошло не так

| Что видите | Причина и решение |
|---|---|
| `RuntimeError: BOT_TOKEN не задан` | Не заполнен `BOT_TOKEN` в `.env`. Заполните и выполните `docker compose up -d`. |
| `TelegramUnauthorizedError` | Неверный токен. Скопируйте заново из @BotFather (без пробелов). |
| `password authentication failed` | Пароль в `.env` поменяли после первого запуска. База запомнила старый. Верните старый пароль. (Если данных ещё нет — `docker compose down -v` и запуск заново.) |
| `TelegramConflictError: terminated by other getUpdates` | Бот с этим токеном запущен где-то ещё (например, на вашем ПК). Остановите вторую копию. |
| `permission denied ... docker.sock` | Не выполнили `usermod -aG docker` или не перезашли в SSH. |
| Бот молчит | `docker compose ps` и `docker compose logs --tail 50 bot` — ошибка будет в логах. |
| `address already in use` | Порты наружу не открываются, так что это обычно не наша проблема — пришлите лог. |
| `git pull`: *Your local changes would be overwritten* | На сервере правили файлы вручную. `git stash` (или `git checkout -- ИМЯ_ФАЙЛА`), затем снова `git pull`. |
| Админу не приходят заказы | Этот Telegram ID есть в `ADMIN_IDS`? Нажимал ли он **Start** в боте? После правки `.env` — `docker compose up -d`. |
| Дилеру не приходят заказы | В карточке дилера **👥 Сотрудники** — есть ли он там? Если нет — новое приглашение. |
| `docker compose logs backup`: *backup FAILED* | Проверьте, что `postgres` работает (`docker compose ps`) и пароль в `.env` тот же, что при первом запуске. |
| Панель не открывается | `docker compose ps` — `web` и `proxy` в `Up`? `ping partsbot.jacmotors.uz` отвечает `192.168.48.103`? (нет — нужна запись в DNS/hosts). Файрвол: `sudo ufw allow from 192.168.0.0/16 to any port 80,443 proto tcp`. `address already in use` — порт 80/443 занят другой программой. |
| `proxy` постоянно перезапускается | `docker compose logs --tail 30 proxy`. `cannot load certificate` — нет файлов в `certs/` или они собраны без перевода строки; `key values mismatch` — ключ не от этого сертификата. |
| Предупреждение «подключение не защищено» | Открыли по IP, а не по имени, или сертификат истёк (см. «Продление сертификата»). |
| В панели «Неверный логин или пароль» | Возьмите новый пароль: в боте `/panel` → 🔑 Новый пароль. Логин — без @. |
| Нет места на диске | `df -h`; старые образы: `docker image prune -f`. Логи и копии ограничены автоматически. |

```
jac-parts-bot/
├── app/
│   ├── main.py                 # точка входа: запуск бота
│   ├── config.py               # чтение .env
│   ├── handlers/
│   │   ├── start.py            # /start, главное меню
│   │   ├── language.py         # выбор и смена языка
│   │   ├── region.py           # выбор и смена региона
│   │   ├── catalog.py          # каталог: модель → категория → деталь
│   │   ├── cart.py             # корзина
│   │   ├── orders.py           # оформление, мои заказы, статусы
│   │   ├── phone.py            # номер телефона (регистрация и смена)
│   │   ├── profile.py          # профиль
│   │   ├── admin.py            # /admin и загрузка Excel
│   │   ├── admin_panel.py      # разделы админ-панели, приглашения сотрудников
│   │   ├── dealer.py           # «Заказы дилера» для сотрудников
│   │   ├── chat.py             # переписка по заказу
│   │   └── fallback.py         # устаревшие кнопки (подключается последним)
│   ├── keyboards/
│   │   ├── main.py             # нижнее меню и кнопки профиля
│   │   ├── language.py         # кнопки выбора языка
│   │   ├── region.py           # кнопки выбора региона
│   │   ├── catalog.py          # кнопки каталога и страниц
│   │   └── phone.py            # кнопка «Отправить номер»
│   ├── middlewares/db.py       # сессия БД + пользователь для каждого сообщения
│   ├── database/
│   │   ├── database.py         # подключение к PostgreSQL
│   │   ├── models.py           # users, regions, models, nodes, parts, dealers, stocks, cart_items, orders, order_items
│   │   └── repositories/       # users, regions, catalog, stocks, cart, orders, admin, staff
│   ├── panel/                  # веб-панель: server.py, templates/, static/
│   ├── services/               # localization.py, catalog.py, excel_import.py, excel_template.py, dealers.py,
│   │                           # import_mapping.py (настройки складской выгрузки)
│   ├── scripts/seed_demo.py    # демо-каталог
│   └── locales/ru.json, en.json, uz.json   # все тексты бота
├── migrations/                 # Alembic: изменения структуры базы
├── tests/                      # автотесты
├── scripts/backup.sh          # ежедневный backup (контейнер backup)
├── backups/                   # копии базы (в Git не попадают)
├── Dockerfile, docker-compose.yml
├── .env.example
└── requirements.txt
```

**Как поменять текст кнопки или сообщения:** откройте `app/locales/ru.json` (или `en`/`uz`),
измените текст справа от двоеточия, затем `docker compose up -d --build`.
